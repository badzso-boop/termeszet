# Többnyelvűség (i18n) és SEO

A nyilvános felület magyarul és angolul érhető el. Az admin felület (`/admin*`) és az
adatbázisban tárolt tartalom (kurzusok, leckék, szolgáltatások, galéria-címek) egyelőre
csak magyar.

## URL-ek és nyelv

- A magyar az alapnyelv, prefix nélkül (`/`, `/galeria`, `/kapcsolat`, `/gyik`, ...), az
  angol `/en` prefixszel és angol slugokkal (`/en`, `/en/gallery`, `/en/contact`, `/en/faq`, ...).
- A nyelvet **mindig az URL határozza meg**. Nincs böngészőnyelv alapú átirányítás, így
  minden URL-nek egyértelmű, indexelhető nyelve van.
- Az útvonaltábla egyetlen helyen van: `frontend/src/i18n/routes.json`. Ebből dolgozik a
  React Router (`App.js`), a nyelvváltó, a szerveroldali SEO (`src/seo.js`) és a sitemap is.
  Új oldalnál ide kell felvenni a kulcsot, mindkét nyelvű útvonallal.
- A régi `/gallery` és `/contact` aliasok és a záró perjeles URL-ek 301-gyel a kanonikus címre
  irányítanak.

## Fordítások

`frontend/src/i18n/locales/<nyelv>/<névtér>.json`, névterek:

| névtér | tartalom |
|---|---|
| `common` | navigáció, lábléc, hírlevél, galéria-nézegető, YouTube szekció, 404 |
| `home` | főoldal |
| `pages` | Kapcsolat, Galéria, GY.I.K., Kurzusok, kurzus-oldal, Profil, Bejelentkezés/Regisztráció |
| `legal` | ÁSZF, Adatvédelem, Felhasználási feltételek (strukturáltan: fejezet/bekezdés/felsorolás) |
| `seo` | oldalankénti `<title>` és meta description |
| `api` | a backend válaszüzeneteinek fordításai (lásd lent) |

Komponensben: `const { t } = useTranslation("pages")`, belső linkhez `useLocalizedPath()`:
`lp("gallery")` → `/galeria` vagy `/en/gallery`.

A frontend teszt (`src/i18n/i18n.test.js`) ellenőrzi, hogy minden nyelvi fájlnak ugyanazok
a kulcsai legyenek, mint a magyarnak. Ha egy szöveget csak az egyik nyelvbe veszel fel,
a teszt elbukik.

## Backend üzenetek

A backend `{ message }` / `{ error }` mezőben **i18n-kulcsot** küld szöveg helyett
(pl. `{ "error": "auth.invalidCredentials" }`). A frontend a `api` névtérből fordítja
(`i18n/apiMessage.js`). Middleware-ből `apiError('upload.invalidImageType')` dobható
(`src/helpers/apiError.js`). Az `app.js` hibakezelője sosem küld nyers hibaüzenetet,
csak kulcsot.

Új kulcsnál vedd fel minden `locales/*/api.json`-ba. A `tests/i18n-keys.test.js` végignézi
a `src/` összes kulcsát, és elbukik, ha valamelyiknek nincs fordítása.

## SEO

- **Szerveroldal** (`src/seo.js`): az SPA `index.html`-jébe kiszolgálás előtt beinjektálja
  az adott URL `<html lang>`, `<title>`, description, canonical, `hreflang` (hu/en/x-default),
  Open Graph, valamint a főoldalon a Person JSON-LD tageket. Így a keresőrobotok és a
  link-előnézetek JavaScript nélkül is jó adatot látnak. Ismeretlen útvonal: 404-es státusz
  és `noindex`. A bejelentkezés, regisztráció, kurzus, profil és admin oldalak `noindex`-esek.
- **Kliensoldal** (`i18n/SeoManager.js`): navigáció után ugyanazzal a logikával
  (`i18n/seoCore.js`, közös a szerverrel) frissíti a `data-seo` tageket.
- `/sitemap.xml` és `/robots.txt` dinamikus. A domain alapértelmezése a `routes.json`
  `siteUrl` mezője, a szerveren a `SITE_URL`, a frontend buildben a `REACT_APP_SITE_URL`
  környezeti változóval felülírható.
- A Docker image a `frontend/src/i18n` mappát `/app/i18n` alá másolja, ebből olvas a szerver.

## Új nyelv felvétele

1. `routes.json`: a `languages` tömbbe, és minden útvonalhoz az új nyelvű path.
2. `locales/<új>/` alá az összes névtér JSON-ja (a teszt jelzi, ha valami hiányzik).
3. `i18n/index.js`: az erőforrások importja; `seoCore.js`: az `OG_LOCALES` bejegyzés.
4. Jobbról balra írt nyelvnél (pl. arab) ezen felül RTL-támogatás is kell (`dir="rtl"`, a
   Tailwind-elrendezés tükrözése).
